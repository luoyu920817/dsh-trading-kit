# 盘后枢纽节点设计（workflow-node）

> 立稿 2026-09-22，来源三轮需求讨论（需求 1/2/3 的接入位置）。
> 前置契约：DB/daily frontmatter 契约（议题 B2，待立约）。

## 1. 定位

「用户复盘之后的数据收集和总结」是全流程的枢纽节点：需求 1 是「你的思考」的
入口，需求 2 是「市场的思考」的入口，需求 3 是两者的合成出口——**输入两条、
出口一个**。本工程阶段 5 的实现对象。

## 2. 节点图

```
盘中（通达信）
   用户：看盘 / 写日记 / 标记            ← 思考的事实源
   dsh：[阶段 6 后] 策略盯盘事件 → 告警留痕
        ↓
盘后枢纽节点（dsh-trader-kit）
   ⓪ 昨日闭环首查（B3 的流程闸门）
   ① 数据收集（定时自动，确定性取数，无 AI 参与）
      TDX 日记 / 标记解析（需求 1 输入）
      行情 / 板块（ZT、LB、炸板）/ 涨停原因 / 概念热度 / 龙虎榜
      台账 / 双轨日志 / 昨日待跟踪 / knowledge_search 召回
   ② 整理与总结（AI 介入，等用户在场）
      需求 1：词表过滤 → 盘面梳理 digest（思考 → 结构化）
      需求 2 增量：digest + 数据 → 事件 skeleton + 题材阶段推移
      需求 3：四层 verdict 合成 + 今日待跟踪登记
   ③ 人工精修（两段式：skeleton → 用户改 → 确认）
   ④ 落盘：events/ · DB/daily/ · 知识卡片/ · 双轨日志
        ↓
周级节点
   需求 2 深度：题材总览重写 + 导图（合成而非每日增量）
   周计划合成：本周 dailies + 台账 → 下周计划
   顺序约束：先深度归纳、后合成周计划（后者消费前者）
        ↓
月级节点（需求 4 分析半）
   情绪周期序列 · 模式胜率 · 判断命中率
```

## 3. 节点内三原则

1. **收集与总结分离，收集自动化**。收集半程是确定性取数（K 线、板块、研究
   数据、日记文件都在本地或固定接口），定在 17:30 龙虎榜更新后自动跑完，
   用户到桌前时 digest 和数据已摆好；总结半程（判断、精修、确认）必须在场。
   不做「等用户发起」的全程手动——每天多一次冷启动成本。
2. **需求 2 拆两个节奏**。盘后只做**增量**（事件 skeleton、题材阶段建议推移、
   新概念登记，分钟级）；**深度归纳**（总览重写、导图、主线复盘）是周级节点
   的活。每天盘后做深度归纳 = 「评论发散太耗时」在需求 2 里的镜像。
3. **节点内有序**。先跑需求 1（日记 digest），再跑需求 2（题材推导把 digest
   作为第四路方向性证据合成进去）——日记里用户注意到的题材方向是题材判断的
   输入之一，不是平行产物。

## 4. 与本工程阶段的对应

- 收集半程（①）：阶段 3 数据面 + 阶段 5 盘后例行 job。
- 总结半程（②③）：阶段 5 复盘 skill（关键词词表 + 两段式协议）。
- 周级/月级节点：阶段 5 后随事件与快照积累逐步启用。
