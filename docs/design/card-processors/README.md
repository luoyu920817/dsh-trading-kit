# 复盘卡片关键词处理：详细设计与审阅入口

日期：2026-10-08。状态：**详细设计草案，供 owner 审阅，尚未实现**。

> 2026-10-09补充：用户已将实施顺序收敛为“先搭关键词框架，再实现预期模块，并在DSH管理页看到调度日志”。当前实施依据改为[关键词框架新版设计](../keyword-framework/README.md)。本目录保留为前版多模块参考；旧保存观察器、完整自建执行调度、编辑/重跑即撤回及旧八步骤不再作为当前实现要求。

本设计采用已选定的方案：**关键词注册表 + 统一后台调度 + 独立功能模块**。当前请求仅授权详细设计；本文涉及的代码文件、接口、默认值和测试均是拟议内容，不能视为已有功能。

## 1. 用户要得到的行为

用户照常在复盘卡片中记录文字和图片，输入 `@预期`、`@模式` 等标记，保存后继续思考下一张卡片。插件识别这些显式意图，登记后台任务，调用数据模块或 DSH Agent。结果出现在原卡片旁，并保留原句、数据日期和历史引用。需要未来验证的预期进入后续交易日回查。
要达到的目的：让这个插件不只是被动的接数据，而是根据数据的输入来触发辅助功能。

这里的“及时处理”定义为：卡片成功保存后立即登记并唤醒调度；模型响应耗时不阻塞保存和编辑。输入过程中只做本地提示，不调用模型。后台处理使用独立 Agent，不向正在使用的主会话插话。

页面展示可以将 `@预期` 变成一个有状态的标签，点开看分析；编辑框和 Markdown 保留原文。分析结果不能把用户的原始思考替换成机器结论。

## 3. 当前项目的事实与限制

以下是 2026-10-08 对当前工作区及本机安装包的只读核验，不是后台能力的运行验收。

| 已核验内容 | 文件依据 | 对本设计的影响 |
| --- | --- | --- |
| 卡片支持新增、编辑、删除、删除单张图片 | `src/review/store.ts` 的 `appendCard`、`updateCard`、`deleteCard`、`deleteCardImage` | 四种成功变更都要进入失效和调度流程，不能只监听 HTTP 新增 |
| 用户卡片与 AI 附注分开解析 | `src/review/md/parse.ts`、`src/tools/review-daily.ts` | 只识别用户卡片正文，AI 结果不递归触发 |
| AI 附注按标的和交易日去重 | `src/review/store.ts` 的 `appendIntoDailyDoc` | 新的多模块、逐卡片结果使用独立存储，不改变每日附注契约 |
| 锚点不包含市场，存在同码跨市场卡片 | `src/review/anchor.ts`、`src/review/ident.ts` | 卡片主键不能只有 `anchor` 或六位代码 |
| 卡片存储有进程内锁、同目录临时文件原子替换 | `src/review/store.ts` | 保留现有写入方式；它不是多进程数据库事务 |
| 扫描在运行时带可选 `qualifier`，部分 TypeScript 类型没声明 | `src/review/store.ts`、`src/tools/review-daily.ts` | 补齐类型；新接口明确携带市场，不复制旧接口遗漏 |
| 现有概念服务没有可证的历史业务日期 | `src/data/concepts.ts` 的 `businessDate: null` 语义 | 当下快照不能伪装成某个历史交易日的概念事实 |
| 现有交易日工具没有完整未来交易日历 | `src/data/trade-date.ts` | 下一交易日回查先按可验证的历史交易日序列确定，不按星期或自然日相加 |
| 主入口只依赖 webServer、connection、tools | `src/index.ts` | agents 等能力作为新增可选适配接入，不能导致旧复盘页无法加载 |
| DSH 公开 Agent API 支持创建、排队后续输入和限定作用域 | 本机 `@deepseek-ai/dsh-agent`、`dsh-agent-loop` 的 README 和类型 | 可复用宿主运行时；接线、模型配置和业务结果回写仍须最小实机验证 |
| frontmatter 的 `patterns`、`drafts` 是预留字段 | `src/review/md/frontmatter.ts` | 本功能不自动填入或改写这些已有字段 |

`DB/stock` 档案只把 `角色` 作为 Agent 口径。`热点标签` 等展示字段不因本次迭代自动进入分析上下文。模式定义来源继续遵守 `docs/design/pattern-unification.md`，不能把股票标签当模式权威。

## 4. 框架职责与业务模块职责

| 组成 | 它负责什么 | 它不替其他组成做什么 |
| --- | --- | --- |
| 关键词解析器 | 从原文识别标记、位置和未知词 | 不判断用户预期对错，不从图片猜标记 |
| 注册表 | 标记对应模块、配置、能力和输出结构 | 不执行 JSON 中的任意代码 |
| 卡片提交观察器 | 保存成功后提供一致的卡片变更快照 | 不发网络请求，不调用模型 |
| 任务存储与调度 | 去重、排队、重试、取消、恢复 | 不替模块理解“预期”和“模式” |
| 上下文构建器 | 读取指定卡片、图片、历史和角色，记录来源 | 不把无来源内容包装成事实 |
| 数据处理模块 | 经既有数据服务获取结构化数据 | 不自由搜索网页，不生成用户判断 |
| Agent 处理模块 | 经宿主运行指定 Skill，提出有依据的整理或候选 | 不自行改用户卡片或模式库 |
| 结果提交服务 | 校验任务、版本、数据结构和证据后保存 | 不把 Agent 停止运行视为结果成功 |
| 页面投影 | 把原文、结果、执行状态和跟踪状态一起展示 | 不作为任务或结果的权威存储 |

## 5. 本轮范围与完成顺序

### 先交付的范围

1. DSH 独立后台 Agent 的最小接线验证。
2. 四个已知关键词的注册、能力说明和配置，其中 `@概念`、`@预期` 先启用；`@模式` 在图片及模式库验收后启用；`@龙虎榜` 保持不可用提示直到数据模块完成。
3. 用户正文识别、可持久化任务、逐卡片结果、修改与删除后的失效。
4. 概念数据补全、预期原句结构化、下一交易日回查与人工确认入口。
5. 页面本地识别提示、模块配置和后台状态展示。
6. 模式候选与证据展示，沿第 6 份文档作为后一批可独立验收的交付。

### 明确后置的范围

- 未写 `@` 时的自动意图猜测、OCR 自动提取标记。
- `@预期:三日` 等参数化语法、按段落分配不同模块。
- 通用流程图编辑器、任意脚本执行、可视化 Prompt 编辑器。
- 模式库自动写回、完整知识图谱、胜率与收益统计。
- 盘中高频盯盘与跨标的全市场自动扫描。

三日/五日预期需要完整交易日序列，配置 schema 可提前预留，但首批页面只开放下一交易日；没有经验证的日期能力时不承诺其他周期。

## 6. 一条完整的使用案例

用户写入：

```text
今天机器人板块回落，但核心票还有承接。
@概念
@预期 明天观察核心票是否重新走强；如果跌破今天低点，这个判断失效。
```

保存后发生：

1. Markdown 成功落盘，原文不变。
2. 解析得到两个模块意图。两个任务都关联同一具体文档、卡片锚点和正文/图片版本。
3. 概念任务经现有服务返回来源标注的实时快照。
4. 预期任务由独立后台 Agent 整理原句。“走强”没有可执行定义时标为人工判断；不擅自补成某个涨幅。
5. 卡片下显示“概念已补全”“预期已整理，待下一交易日回查”。
6. 后续回查并列原句、实际数据和机器建议。用户可以确认兑现、证伪、失效或继续保留。
7. 如果用户在分析完成前编辑原句，旧任务结果不得覆盖新版卡片；如果删掉 `@预期`，停止该来源产生的后续回查，已生成的历史证据仍可查看。

## 7. 对既有裁决的显式调整

旧 `review-loop` 的 D-1 为当时的手动整理入口选择 `ctx.conversation.send`，并否决依赖未公开服务的程序化 Agent。**本次新需求新增使用 DSH 已公开 `ctx.agents` API 的可选后台能力**。现有手动整理仍可使用，本插件仍不自建 Agent Runtime。

旧每日汇总禁止将用户主观判断写成事实附注。本次新产物允许“引用并整理用户观点”，但必须明确 `userQuote` 与 `agentInterpretation` 两类来源；它不是修改旧附注规则的理由。

新结果与跟踪文件限定在既有 `DB/review/` 写分区；不新增 `DB/expectations/`，不改 `DB/stock` 或模式权威文件。新配置和文件布局需随实现登记到 `src/paths/mapping.ts`，不靠任意路径拼接。

## 8. 审阅时优先看的决定

请优先审阅以下具体取舍；其余章节已按这些默认决定展开，不以开放问题阻塞文档。

| 决定 | 本设计默认值 | 调整会影响哪里 |
| --- | --- | --- |
| 触发时间 | 保存成功后；编辑时只本地提示 | 关键词识别、成本、后台队列 |
| 处理范围 | 整张卡片 | 解析器和多标记的语义 |
| 替换关键词 | 仅展示层转成状态标签，原文保留 | 页面、原句追溯 |
| 执行隔离 | 每次任务尝试一个独立短生命周期 Agent；初始最多一个 Agent 并发 | 宿主适配、任务取消与成本 |
| 结果存储 | `DB/review` 内独立 JSON 记录，正文不回写 | 页面、工具、Obsidian 阅读面 |
| 预期判断权 | 机器给建议，用户确认最终业务状态 | 跟踪与后续统计 |
| 初始回查周期 | 下一交易日盘后 | 日期能力和数据历史性 |
| 自定义扩展 | 后端 JSON 绑定受控模块或已安装 Skill；页面只调业务参数 | 配置与模块 schema |

本设计没有修改生产代码、配置、vault 或宿主进程。待文档审阅完成，再按第 7 份文件的顺序进入回归测试和实现。
