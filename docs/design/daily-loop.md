# 每日闭环六步（daily-loop，需求 3）

> 立稿 2026-09-22，来源三轮需求讨论。实现落点：阶段 5 复盘 skill；
> 契约依赖：DB/daily frontmatter（议题 B2）。

## 0. 病根诊断

「总是没有闭环、得不出多头空头」**不是纪律问题，是流程排序问题**——待跟踪项
没有强制回查点，自然死亡。修法 = 把回查做成流程闸门：**闭环不靠自律、靠流程
顺序**。

## 1. 六步机制

1. **强制收口**。四层 verdict（指数 / 情绪 / 题材 / 个股）必须落枚举值
   （多 / 空 / 中性），每个判断必须带**失效条件**——失效条件是闭环的钩子，
   没有它的判断无法被检查。
   例：`指数：多 · 依据：缩量回踩 20 日线不破 · 失效：放量跌破 20 日线或
   成交额连续 3 日 <1.5 万亿`。
2. **结构化登记，单一事实源**。待跟踪项当日落 `DB/daily/<date>.md`
   frontmatter（类型 / 内容 / 验证方式[自动可查|人工判断] / 状态 / 登记日）。
   不建独立滚动台账——未收口项从最近 N 天 daily 文件派生扫描，免双写漂移。
3. **次日自动核销**。自动可查项对 TDX 数据面核验（价格 / 板块 / 事件兑现），
   机器出「建议核销 / 证伪」，人裁决后才落状态；判断类留人工。自动化比例随
   失效条件的可查化程度自然提升。
4. **老化升级**。挂满 N 个交易日（建议 5，待拍板）未验证 → 强制三选一：
   升级为 vault 事件卡 / 作废（失效 + 一句理由）/ 显式挂起（周报点名）。
   「待跟踪」不允许无限尾巴。
5. **周级命中统计**。周计划合成加一步——本周每日 verdict 对照实际走势的
   命中率（指数层方向、题材主线兑现度）。判断质量本身成为被统计对象。
6. **词汇统一**。待跟踪项 = 轻量事件卡，复用 vault 既有状态模型
   （待验证 → 已兑现 / 已证伪 / 已失效）与 credibility 映射，不发明第二套
   todo 词汇。全系统只有一套闭环模型。

## 2. 流程闸门（与盘后枢纽的接合）

复盘 skill 第 0 步 = 昨日首查，未收口项**强阻塞**（处理完才进今日收集）。
「昨天没收口，今天不让开始」——这就是闭环的实现机制。

## 3. 核销写回边界（议题 B4，待立约）

- 机器不直接改状态：核验产出建议、人裁决后才落。
- 写回形态：状态写回原条目（同 vault 事件判断字段人工回填模式）+ 核销动作
  留痕于次日文件（单一事实源 + 审计线）。
- 需在写分区细则显式定义：**会话内经用户确认的判断字段写回 = 授权回填**，
  与「不代改人工判断字段」红线的关系以此澄清。

## 4. 与需求 4 的咬合

verdict、待跟踪、核销记录每天落 `DB/daily/`，本身就是采集的一部分——
**判断命中率序列也是不可回溯、只能从今天开始积累的数据**。
