# 模式与交易的统一（pattern-unification，知行合一的词汇层）

> 立稿 2026-09-22，来源三轮需求讨论。实现落点：F 线横切——阶段 5 打地基
>（verdict 打模式标签），阶段 6 完成量化半挂钩，OPT 回路随统计积累启用。

## 0. 现状约束（决定设计的分工）

- vault 三体系（超短博弈 / 价值投机 / 期货套利 + 价格行为学）是模式权威。
- 策略引擎的量化范式（6 个）与 vault 模式无关联词。
- 双轨日志只记「做了什么」，why 归决策记录（红线不动）。
- holdings 台账只有持仓，没有模式字段。

统一 = **模式 id 一词到底**：`命名空间.模式`（如 `超短.龙头首阴`、
`价投.趋势回踩20日`、`期货.宏观对冲`）。

## 1. 四个统一

1. **统一词汇——模式注册表**。模式 id 写进 vault 模式文件 frontmatter；
   本工程侧注册表 = vault 派生**只读视图**（框架规则在 canvas、模式 id 在
   md，canvas 只读解析）。新增模式先写 vault，工程侧永远只读。
2. **统一记账——尊重既有分工的 join**。模式归属记**思考侧**：verdict 个股层
   写明「关注 XX 是 `超短.龙头首阴` 的实例 + 一句理由」；操作侧 journal /
   台账按**日期 + 标的**与思考侧 join。join 不上的交易 = **无模式交易占比**，
   即知行合一偏离度指标，周报点名。可选轻量：journal 条目加可选模式指针
   （只是 id，不写 why，红线不破）。
3. **统一分层——每模式分解两半**。可量化条件（→ screener / strategy 挂
   `patternId`，回测 / 盯盘 / TDX 选股语句导出三面同源）+ 判断性条件
   （情绪周期位置、题材发酵期判断 → 留在复盘判断层，靠知识召回与统计辅助）。
   **不强行量化人化判断**——硬塞公式是这类系统最常见的死法。
4. **统一回路——统计反哺模式迭代**。per-pattern 统计（胜率 / 盈亏比 /
   实际持有期 vs 模式预期 / 仓位合规度）→ 模式迭代建议 → vault 模式文件修改
   （人工确认闸门，OPT 反馈既有设计）。模式是资产，统计是证据，迭代是资产
   变更；回路终点回 vault。

## 2. 时间不可逆原则

模式归属和需求 4 的快照一样，是只能从今天开始积累的资产——复盘当天不写
「这笔是哪个模式的思考」，一周后回溯就是猜。因此：

- 模式 id 词汇**提前到阶段 5 第一天**进 verdict（粒度可先体系级 + 已明确的
  几个模式级混跑）；
- 完整模式工程（canvas 解析、买前评分、OPT 闭环）按阶段慢慢建，
  **join key 不能等**。

## 3. 待拍板（随议题 F1/F2）

- 首版粒度：建议直接模式级（十几个），体系级太粗统计无意义；id 稳定不重命名。
- journal 可选模式指针的字段名与 skill 契约修订时机。
