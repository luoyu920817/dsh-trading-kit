## 已确认的产品方向与约束

这是个人 A 股研究工作流插件，后续希望覆盖盘面梳理、题材推导、每日闭环、历史统计与策略观察。市场数据只读，不设计自动交易执行。

通达信内置复盘页面承担内容编辑、数据和事件来源；用户无需登录 DSH 或复制 token 即可保存、修订和删除。后台在成功存储后接收事件，回读内容，解析如 `@预期` 的关键词并映射工作流，持久登记、去重，由 DSH 独立执行。配置、任务、日志、结果、取消和显式重跑位于 DSH。不要再给输入页加登录入口，也不要为了免登录把整个管理 API 放开；既有本机来源检查与页面自动写凭据需保留。

沿用开放工作流的单 `execute` 契约：统一框架管理来源、身份、版本、预算、取消、恢复和结果；业务步骤由各工作流自行组织。不要恢复六方法、公共 stage 或强制的预期观察协议。可研究可选进度上报、内部组合、延迟任务和人工交互，但必须说明是否需要接口扩展、哪些工作流可以不使用、如何兼容现有实现。

保留来源市场/代码/日期隔离、去重、来源与定义版本核验、旧版本和迟到结果保护、取消资源清理、恢复，以及每次真实 Agent 激活前的预算控制。`jobs`或`agentFactory`接口存在、模型字段已填写，都不能证明真实模型执行成功。缺能力时明确等待；生产不得用固定结果或假 Agent 冒充成功。

当前 `@预期` 只整理卡片中的预期、可观察条件和后续核验方式。次日自动回查、行情取证和复杂观察属于后续可选演进。当前仅订阅插件实际保存/修订/删除事件；外部编辑器修改 vault 没有通用文件 watcher，保存成功到首次登记之间也需检查崩溃窗口。不要将待设计能力描述成已实现。

业务目录沿数据根的相对路径，标的和模式目录可选择后显式保存；Agent工作目录是不同概念。单工作流执行许可、全局自动执行、模型配置、预算和并发要明确区分。默认自动执行关闭；实际用户环境的即时状态无法仅从 GitHub 判断。

保持增量演进、复用宿主能力、少依赖、可审查可回滚。不要为了“可扩展”优先搭建重型分布式平台或拖拽编辑器；若推荐引入依赖，给出具体收益、替代方案和必要性。
